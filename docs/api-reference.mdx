## GraphRAG (Facade)

The main entry point. Three primary operations: `ingest()`, `retrieve()`, and `completion()`. Tables go through the same `ingest()`; see [Structured Ingestion](#structured-ingestion).

```python
from graphrag_sdk import GraphRAG
```

### Constructor

```python
GraphRAG(
    connection: FalkorDBConnection | ConnectionConfig,
    llm: LLMInterface,
    embedder: Embedder,
    ontology: Ontology | None = None,
    retrieval_strategy: RetrievalStrategy | None = None,
    embedding_dimension: int = 256,
    *,
    enable_cypher: bool = False,
    schema: Ontology | None = None,  # deprecated alias of ontology=
)
```

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `connection` | `FalkorDBConnection \| ConnectionConfig` | required | Database connection, or a config to create one |
| `llm` | `LLMInterface` | required | LLM provider for extraction, keyword extraction, the dedup judge and answer generation |
| `embedder` | `Embedder` | required | Embedding provider |
| `ontology` | `Ontology \| None` | `None` | Entity and relation types for extraction, and any `tables=` declared on it. Empty means the ontology already stored for the graph is used, or, on a graph with none, the 11 built-in default entity types are seeded on first use |
| `retrieval_strategy` | `RetrievalStrategy \| None` | `None` | Default retrieval strategy (`MultiPathRetrieval` if None) |
| `embedding_dimension` | `int` | `256` | Dimension of the vectors `embedder` produces |
| `enable_cypher` | `bool` | `False` | Add the text-to-Cypher retrieval path to the default `MultiPathRetrieval`. It answers counts and aggregates over declared columns, at the cost of an extra LLM call per question (up to 3 when a generated query fails validation and is regenerated). Ignored when `retrieval_strategy` is supplied, since that strategy decides for itself |
| `schema` | `Ontology \| None` | `None` | Deprecated; use `ontology=`. Passing both raises `TypeError` |

**Public attributes:** `llm`, `embedder`, `ontology`. The storage layer is private (`_graph_store`, `_vector_store`); use `get_statistics()`, `query()` and `delete_all()` instead of reaching into it. `rag.schema` still works as a deprecated alias of `rag.ontology`.

`GraphRAG` is an async context manager (`async with GraphRAG(...) as rag:`), which closes the connection on exit. It is single-entry: use one `async with` block per instance. `await rag.close()` closes the connection explicitly.

Every FalkorDB call goes through a connection that checks the server version once, before its first query, and raises `FalkorDBVersionError` for a server older than 4.20. See [Configuration](/configuration#falkordb-server-version).

### ingest()

```python
async def ingest(
    source: str | list[str] | None = None,
    *,
    text: str | None = None,
    document_id: str | None = None,
    record_loader: RecordLoaderStrategy | None = None,
    strict_mapping: bool = False,
    loader: LoaderStrategy | None = None,
    chunker: ChunkingStrategy | None = None,
    extractor: ExtractionStrategy | None = None,
    resolver: ResolutionStrategy | None = None,
    max_concurrency: int = 3,
    ctx: Context | None = None,
) -> IngestionResult | list[IngestionResult | Exception] | StructuredIngestionResult
```

Build a knowledge graph from one or more sources. Two input modes, mutually exclusive: **file mode** (`source`, one path or a list) and **text mode** (`text`). When a list of sources is provided, documents are ingested in parallel with bounded concurrency; one bad source does not abort the batch.

A `.csv`, `.tsv`, `.psv` or `.tab` is read as **records, not prose**: its mapping is looked up in the ontology by filename (see [Structured Ingestion](#structured-ingestion)), no model extracts from it, and a `StructuredIngestionResult` is returned. A table may not appear in a list (each is written on its own, so `ValueError` is raised before anything is ingested), and `chunker`, `extractor` and `resolver` are rejected for one; identity across sources is judged by `finalize()`. Pass `loader=TextLoader()` to read a CSV as prose anyway.

Re-ingesting a document whose text is byte-identical to what the graph already holds is a no-op: the call returns before chunking with `chunks_indexed=0` and `metadata["skipped_unchanged"] = True`, and makes no extraction or embedding calls for the document (a new `GraphRAG` instance still sends its one-time embedder dimension probe). Chunk ids are derived from the document id, position and text, so re-ingesting the same file never duplicates its chunks. The content hash is recorded only when every write completed; if anything came up short, `metadata["incomplete_writes"]` lists it and the next ingest repairs the document instead of skipping it. To re-extract unchanged content (after changing the ontology, chunker, extractor or model), use `update(..., force=True)`.

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `source` | `str \| list[str] \| None` | `None` | File path (or list of paths). Required unless `text=` is given |
| `text` | `str \| None` | `None` | Raw text (single document; skips the loader). `loader` is rejected with it |
| `document_id` | `str \| None` | `None` | Stable handle for `update()` and `delete_document()`. Defaults to the normalised path for a document (a URI such as `https://...` or `s3://...` is kept verbatim), to the table's name for a table, and to `text-<16 hex>` (a SHA-256 prefix of the text) in text mode. Must not contain `__pending__`. Not allowed with a list source. `ingest("employees_2026Q3.csv", document_id="employees.csv")` re-syncs `employees.csv` |
| `record_loader` | `RecordLoaderStrategy \| None` | `None` | How a table is read (`CsvRecordLoader` if None). Tables only |
| `strict_mapping` | `bool` | `False` | Fail when a table has a column its mapping never reads, instead of ignoring the column. Tables only |
| `loader` | `LoaderStrategy \| None` | `None` | Custom loader. If None: `.pdf` uses `PdfLoader`, `.md` uses `MarkdownLoader`, everything else `TextLoader`. Passing one for a `.csv` reads it as prose |
| `chunker` | `ChunkingStrategy \| None` | `None` | Custom chunker (`SentenceTokenCapChunking()`, 384 tokens, if None). Rejected for a table |
| `extractor` | `ExtractionStrategy \| None` | `None` | Custom extractor (`GraphExtraction` with the instance's `llm` if None). Rejected for a table |
| `resolver` | `ResolutionStrategy \| None` | `None` | Custom resolver (`ExactMatchResolution(llm=None, cross_label_merge=False)` if None). Rejected for a table |
| `max_concurrency` | `int` | `3` | Max parallel ingestions (list input only) |
| `ctx` | `Context \| None` | `None` | Execution context |

**Returns:** `IngestionResult` for a single document, `StructuredIngestionResult` for a table, `list[IngestionResult | Exception]` (aligned by index) for a list of sources. Failures in a list are also logged at WARNING.

<Note>
  Text mode with no `document_id` derives the id from the text, so two calls with the same text are one Document and the second is a no-op. Pass a distinct `document_id` per call to keep identical texts as separate documents.
</Note>

### update()

```python
async def update(
    source: str | None = None,
    *,
    text: str | None = None,
    document_id: str | None = None,
    loader: LoaderStrategy | None = None,
    chunker: ChunkingStrategy | None = None,
    extractor: ExtractionStrategy | None = None,
    resolver: ResolutionStrategy | None = None,
    cache_unchanged_chunks: bool = False,
    if_missing: Literal["error", "ingest"] = "error",
    force: bool = False,
    record_loader: RecordLoaderStrategy | None = None,
    strict_mapping: bool = False,
    ctx: Context | None = None,
) -> UpdateResult
```

Re-sync a previously ingested document or table through a crash-safe cutover. Unchanged content (same content hash) is a no-op; entities left with no `MENTIONED_IN` edge are removed with their `RELATES` edges. A table re-syncs as a snapshot: rows deleted from the export leave the graph. A Document records how it was written, so `update()` cannot re-read a table as prose or a document as records. See [Incremental Updates](/incremental-updates).

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `source` / `text` | `str \| None` | `None` | Mutually exclusive, as for `ingest()` |
| `document_id` | `str \| None` | `None` | The Document to update. Defaults to the id `ingest(source)` derives. Required in text mode |
| `loader`, `chunker`, `extractor`, `resolver` | strategies | `None` | Per-call overrides, as for `ingest()`. For a table, `chunker` and `extractor` raise `ValueError` (as does `cache_unchanged_chunks=True`), and `resolver` is ignored |
| `cache_unchanged_chunks` | `bool` | `False` | Rebuild chunks whose text is byte-identical to an existing chunk of this document from the live graph instead of re-extracting them. Stats in `metadata["cache_stats"]` (`cached_chunks`, `extracted_chunks`) |
| `if_missing` | `"error" \| "ingest"` | `"error"` | `"error"` raises `DocumentNotFoundError` for an unknown id; `"ingest"` ingests it |
| `force` | `bool` | `False` | Re-extract even when the content hash is unchanged |
| `record_loader`, `strict_mapping` | | `None`, `False` | Per-call overrides for a table, as for `ingest()` |
| `ctx` | `Context \| None` | `None` | Execution context |

**Returns:** `UpdateResult`. For a table, the structured counts (`records`, `entities`, `references`, `edges`, and the rest of `StructuredIngestionResult.as_dict()`) are in `metadata`.

### delete_document()

```python
async def delete_document(
    document_id: str,
    *,
    if_missing: Literal["error", "ignore"] = "error",
) -> DeleteDocumentResult
```

Remove one Document, its chunks, the `RELATES` facts whose only provenance was those chunks, and the entities only it mentioned. Entities other documents mention are kept. `if_missing="ignore"` returns an empty result for an unknown id instead of raising `DocumentNotFoundError`. A table is deleted by its name; for a table, prefer `drop_table()`, which also removes its signed properties and its mapping.

### apply_changes()

```python
async def apply_changes(
    *,
    added: list[str] | None = None,
    modified: list[str] | None = None,
    deleted: list[str] | None = None,
    loader: LoaderStrategy | None = None,
    chunker: ChunkingStrategy | None = None,
    extractor: ExtractionStrategy | None = None,
    resolver: ResolutionStrategy | None = None,
    cache_unchanged_chunks: bool = False,
    max_concurrency: int = 3,
    update_concurrency: int = 1,
    ctx: Context | None = None,
) -> ApplyChangesResult
```

Apply a batch of file changes: `deleted` → `delete_document()`, `modified` → `update(if_missing="ingest")`, `added` → `ingest()`, in that order. Per-file failures are captured as `BatchEntry` entries; the batch never raises for one file. An id that appears in two of the lists raises `ValueError` before anything runs.

Tables are accepted in `added` and `modified`. Each table is written on its own through the structured path; prose files are batched as before. The `chunker`, `extractor`, `resolver` and `cache_unchanged_chunks` overrides apply to the prose in the batch, not to a table. A table's entry is an `IngestionResult` (or `UpdateResult`) with the structured counts in `result.metadata`.

`apply_changes()` does **not** call `finalize()`. Call `finalize()` once after the batch. Leave `update_concurrency` at `1`; see [Incremental Updates](/incremental-updates).

### retrieve()

```python
async def retrieve(
    question: str,
    *,
    strategy: RetrievalStrategy | None = None,
    reranker: RerankingStrategy | None = None,
    ctx: Context | None = None,
) -> RetrieverResult
```

Retrieve context from the knowledge graph without generating an answer. Use this to inspect retrieved context or pass it to your own LLM. The default `MultiPathRetrieval` still makes one LLM call for keyword extraction (and one more for text-to-Cypher when enabled).

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `question` | `str` | required | The user's question |
| `strategy` | `RetrievalStrategy \| None` | `None` | Override the retrieval strategy for this call |
| `reranker` | `RerankingStrategy \| None` | `None` | Optional reranking after retrieval |
| `ctx` | `Context \| None` | `None` | Execution context |

**Returns:** `RetrieverResult`

If documents were ingested without a deduplication pass since, the first read logs a one-time WARNING reminding you to call `finalize()`.

### completion()

```python
async def completion(
    question: str,
    *,
    history: list[ChatMessage | dict[str, str]] | None = None,
    strategy: RetrievalStrategy | None = None,
    reranker: RerankingStrategy | None = None,
    prompt_template: str | None = None,
    rewrite_question_with_history: bool = False,
    return_context: bool = False,
    ctx: Context | None = None,
) -> RagResult
```

Full RAG pipeline: retrieve context and generate an answer. Messages are always sent through `LLMInterface.ainvoke_messages()` as `[system, *history, user]`.

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `question` | `str` | required | The user's question |
| `history` | `list[ChatMessage \| dict] \| None` | `None` | Conversation history (see below) |
| `strategy` | `RetrievalStrategy \| None` | `None` | Override the retrieval strategy for this call |
| `reranker` | `RerankingStrategy \| None` | `None` | Optional reranking after retrieval |
| `prompt_template` | `str \| None` | `None` | Template for the current turn, filled with `str.format(context=..., question=...)`, so any other literal brace must be doubled. Applied with or without history. A custom template turns off the `</context>` neutralisation and the delimited system prompt |
| `rewrite_question_with_history` | `bool` | `False` | With history, rewrite the question into a standalone form with one extra LLM call before retrieval |
| `return_context` | `bool` | `False` | Include the `RetrieverResult` in `RagResult.retriever_result` |
| `ctx` | `Context \| None` | `None` | Execution context |

**Returns:** `RagResult`. `metadata` holds `model`, `num_context_items`, `strategy` (the strategy class name), `has_history` and `retrieval_query` (the query actually used for retrieval).

**Conversation history:**

History accepts a list of `ChatMessage` objects or plain dicts with `role` and `content` keys. Supported roles: `"system"`, `"user"`, `"assistant"`. A dict with a missing key, an unknown role or non-string content raises `ValueError`; an entry that is neither a `ChatMessage` nor a dict raises `TypeError`. If the first message has `role="system"`, it is used as the system prompt as-is; otherwise the SDK's own system prompt is used.

```python
from graphrag_sdk import ChatMessage

# Using ChatMessage objects
result = await rag.completion(
    "What happened next?",
    history=[
        ChatMessage(role="user", content="Who is Alice?"),
        ChatMessage(role="assistant", content="Alice is an engineer."),
    ],
)

# Using plain dicts
result = await rag.completion(
    "Tell me more.",
    history=[
        {"role": "user", "content": "What is Acme?"},
        {"role": "assistant", "content": "A tech company."},
    ],
)
```

### query()

```python
async def query(cypher: str, params: dict[str, Any] | None = None) -> list[list[Any]]
```

Run a Cypher query against your own graph and return its rows, each a list of column values in the order returned; an empty list when nothing matched. Use it to check what an ingest wrote or to aggregate over declared columns yourself. It runs exactly the Cypher you pass, with no rewriting and **no read-only enforcement**: treat it like a database console. Pass values through `params` (`$name`), never string formatting.

```python
rows = await rag.query(
    "MATCH (p:Person)-[r:RELATES]->(o:Organization) "
    "WHERE r.rel_type = 'WORKS_AT' AND o.name = $company "
    "RETURN avg(p.employees__age) AS mean_age",
    {"company": "Acme Corp"},
)
```

A table's columns are stored under its signature (`employees__age` for `employees.csv`); see [Structured Ingestion](#structured-ingestion).

### get_statistics() and delete_all()

```python
async def get_statistics() -> dict[str, Any]
async def delete_all() -> None
```

`get_statistics()` returns `node_count`, `edge_count`, `entity_types`, `relationship_types`, `relates_edge_count`, `mention_edge_count`, `embedded_relationship_count` and `graph_density`. SDK system nodes (`__GraphRAGConfig__`, `__GraphRAGProcessing__`) are not counted.

`delete_all()` drops the data graph and its paired `<graph_name>__ontology` graph. Irreversible. A later `ingest()` on the same instance re-creates indexes and re-registers the ontology.

### Ontology methods

```python
async def get_ontology() -> Ontology
async def refresh_ontology() -> Ontology
async def set_ontology(ontology: Ontology) -> Ontology
async def save_ontology(path: str, *, indent: int = 2) -> None
```

The ontology is persisted in `<graph_name>__ontology`. `get_ontology()` registers the constructor's ontology on first use and returns the persisted one; `refresh_ontology()` reloads it (for changes another process made); `set_ontology()` swaps the working ontology between ingests (additive: new labels are accepted, an existing label may not be modified, a retyped property raises `OntologyContradictionError`); `save_ontology()` writes it as JSON, for `Ontology.from_file()`.

Every change to the working ontology (first load, `set_ontology()`, each evolution method, a table declaring typed columns) is passed to the configured retrieval strategy through `RetrievalStrategy.set_ontology()`, so generated Cypher always sees the current schema.

### Ontology evolution methods

Change the ontology of a populated graph. Full semantics in [Ontology Evolution](/ontology-evolution).

| Method | Returns | What it does |
|--------|---------|--------------|
| `set_entity_description(label, description)` | `Ontology` | Declaration only |
| `set_relation_description(label, description)` | `Ontology` | Declaration only |
| `set_attribute_description(owner_label, attribute_name, description)` | `Ontology` | Declaration only |
| `add_entity(entity)` | `Ontology` | Declare a new entity type |
| `add_relation_pattern(rel_label, source, target)` | `Ontology` | Declare a `(source, target)` pattern |
| `rename_entity(old, new)` | `Ontology` | Relabel every node; a table mapping that names the label (its rows or a `Link` target) is renamed with it |
| `rename_attribute(owner_label, old_name, new_name)` | `Ontology` | Entity owners only |
| `rename_relation(old, new)` | `Ontology` | Recreates every `[:old]`-typed edge (the edges `backfill_relation_pattern()` writes) as `[:new]`. `RELATES` edges whose `rel_type` is `old` are not changed |
| `drop_entity(label)` | `Ontology` | Delete every node with the label. Raises `ValueError` while a table maps rows to the label or links to it: `drop_table()` the source first, or `rename_entity()` |

| `drop_relation_pattern(rel_label, source, target)` | `Ontology` | Deletes `[:rel_label]`-typed edges between the two labels. `RELATES` edges are kept |
| `drop_table(source)` | `Ontology` | See below |
| `add_attribute(owner_label, attribute, *, concurrency=4, dry_run=False)` | `EvolutionResult` | Declare an attribute and fill it from stored chunks with the LLM |
| `drop_attribute(owner_label, name)` | `Ontology` | Remove an attribute from every instance |
| `backfill_entity(label, *, scope="all", concurrency=4, dry_run=False)` | `BackfillResult` | Re-scan chunks for instances of a label |
| `backfill_relation_pattern(rel_label, source, target, *, scope="candidate-pairs", concurrency=4, dry_run=False)` | `BackfillResult` | Re-scan co-mention chunks for edges of a pattern |

### drop_table()

```python
async def drop_table(source: str) -> Ontology
```

Take a table out of the graph:

1. its Document and record chunks, through `delete_document()`, which also removes any entity only those rows mentioned;
2. every property it signed on entities that survive, and the identity it gave them (`entity_key`, `is_stub`), unless another table still keys the node;
3. its stored mapping, so the next `ingest()` of that filename is proposed a mapping afresh.

The label stays in the ontology; `drop_entity()` removes a label nothing uses. `source` is matched on its basename, like `ingest()`. It is also how you refuse a mapping the SDK proposed.

**Raises:** `ValueError` when no table of that name is in the ontology.

### deduplicate_entities()

```python
async def deduplicate_entities(
    *,
    batch_size: int = 500,
    judge: DedupJudge | None = None,
    dedup_all: bool = False,
    fuzzy: bool | None = None,                  # deprecated: False is ignored with a warning, True raises ValueError
    similarity_threshold: float | None = None,  # deprecated and ignored, with a warning
) -> int
```

Cross-document entity deduplication; `finalize()` calls it. Every run has a judge: `judge` is any [`DedupJudge`](#deduplication-judges), and `None` is `LLMJudge` with the instance's `llm`. Anything else, `judge=False` among them, raises `TypeError` before any work.

- **Incremental.** Only the pending entities are checked: those ingest wrote without a name vector, and those a `pending` system record lists. They are compared with the rest of the graph through the `__Entity__` vector index, never by reading every entity. A second call with nothing pending does no work and asks the judge nothing. `dedup_all=True` checks every entity and retries the unresolved ones.
- **Phase 1, exact name.** Groups by canonical name and label (case, accents, punctuation, `&`, inner dots, a leading English article, `Surname, Given` inversion, common abbreviations and one trailing legal form are normalised; word order is not). An acronym joins its unique same-label long form. A group holding a table row merges by rule; a group of extracted mentions only goes to the judge.
- **Phase 2, judged.** Each pending entity's nearest names form small candidate sets; the judge partitions each set once, reading names, labels, aliases, descriptions and the values of the attributes the ontology declares. Agreed groups merge; a "different" answer writes nothing. Two keyed table rows, and a mention two such rows could own, are never put to the judge.
- **Crash-safe.** Every merge is decided before any is written, sealed in a merge plan, and applied one atomic query per merge, moving every relationship of every type. An interrupted run is finished by the next one.
- **One run per graph.** A second concurrent run raises `DedupRunActiveError`; a run that stalls past its 10-minute heartbeat is taken over. `update()` and deletes may run meanwhile; a merge they affect is skipped and decided again next run.
- An entity whose check did not complete stays pending; after 3 judged runs without a usable verdict it is unresolved (reported, never merged automatically).

**Returns:** Number of duplicate entities merged. See [Storage](/storage) for the survivor rule and what a merge keeps.

### finalize()

```python
async def finalize(
    *,
    judge: DedupJudge | None = None,
    dedup_all: bool = False,
) -> FinalizeResult
```

Run all post-ingestion steps after the documents and tables are ingested. Call it once per batch, not once per file. Bundles:

1. Remove NULL-name stub entities left by legacy writes (only nodes no mapping wrote).
2. `deduplicate_entities(judge=..., dedup_all=...)`: exact-name and acronym dedup of the pending entities, then one judge pass over their nearest names. Dedup writes each entity's name embedding, listing the entity as pending first; `entities_embedded` counts them.
3. `embed_relationships()`: fact-text embeddings on `RELATES` edges.
4. `ensure_indices()`: all indexes, waiting until FalkorDB reports them built.
5. A consistency report over the whole graph, logged at WARNING and returned on the result.

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `judge` | `DedupJudge \| None` | `None` | The dedup judge. `None` is `LLMJudge` with the instance's `llm`; give it a gpt-4.1-class model (`finalize(judge=LLMJudge(gpt41))`): on the benchmark corpus a gpt-4.1-class judge made 9 wrong merges where gpt-4o-mini made 51 |
| `dedup_all` | `bool` | `False` | Check every entity instead of only the pending ones, and retry the unresolved ones. Run it once after entity vectors were written outside `finalize()` |

`finalize()` calls the LLM (the judge). To keep dedup LLM-free, pass a `DedupJudge` of your own. `finalize()` does not call `backfill_entity_embeddings()`.

**Returns:** [`FinalizeResult`](#finalizeresult).

### Sync Wrappers

Each wrapper has the same keyword arguments as its async counterpart and runs it in `asyncio.run()`, so it must not be called from inside a running event loop.

```python
def ingest_sync(source=None, *, text=None, document_id=None, loader=None, chunker=None,
                extractor=None, resolver=None, max_concurrency=3, record_loader=None,
                strict_mapping=False, ctx=None) -> IngestionResult | list[IngestionResult | Exception] | StructuredIngestionResult
def update_sync(source=None, *, text=None, document_id=None, loader=None, chunker=None,
                extractor=None, resolver=None, cache_unchanged_chunks=False, if_missing="error",
                force=False, record_loader=None, strict_mapping=False, ctx=None) -> UpdateResult
def delete_document_sync(document_id, *, if_missing="error") -> DeleteDocumentResult
```

## Ingestion Strategies

### LoaderStrategy (ABC)

```python
class LoaderStrategy(ABC):

```

**Built-in:** `TextLoader(encoding="utf-8")` (exported), `PdfLoader()` (`graphrag_sdk.ingestion.loaders.pdf_loader`, needs the `pdf` extra), `MarkdownLoader(encoding="utf-8")` (`graphrag_sdk.ingestion.loaders.markdown_loader`, needs the `markdown` extra). ### ChunkingStrategy (ABC)

```python
class ChunkingStrategy(ABC):
    @abstractmethod
    async def chunk(self, text: str, ctx: Context) -> TextChunks: ...
```

**Built-in:**
- `SentenceTokenCapChunking(max_tokens=384, overlap_sentences=2, encoding_name="cl100k_base")` (the `ingest()` default)
- `FixedSizeChunking(chunk_size=1000, chunk_overlap=100)` (characters)
- `ContextualChunking(llm, base_chunker=None, max_tokens=384, overlap_sentences=2, encoding_name="cl100k_base", max_document_tokens=16_000)`
- `StructuralChunking(fallback_chunker=None, max_tokens=384, encoding_name="cl100k_base", overlap_sentences=2)` (`graphrag_sdk.ingestion.chunking_strategies.structural_chunking`)
- `CallableChunking(fn, *, strategy_name="custom")`

Pass `SentenceTokenCapChunking(max_tokens=512)` to keep a larger chunk size. Smaller chunks mean more extraction calls; see [Configuration](/configuration#chunking).

### ExtractionStrategy (ABC)

```python
class ExtractionStrategy(ABC):
    @abstractmethod
    async def extract(self, chunks: TextChunks, ontology: Ontology, ctx: Context) -> GraphData: ...
```

**Built-in:**
- `GraphExtraction(llm, *, entity_extractor=None, coref_resolver=None, entity_types=None, relation_types=None, max_concurrency=None)`. `entity_types=None` selects `DEFAULT_ENTITY_TYPES` (11 labels); `relation_types=None` selects `DEFAULT_RELATION_TYPES`, a 31-label UPPER_SNAKE_CASE vocabulary (`LOCATED_IN`, `PART_OF`, `EMPLOYED_AT`, `AUTHORED`, ...) the step-2 prompt asks the LLM to prefer; off-list labels are still kept. Pass `relation_types=[]` for open-vocabulary labels. Both are overridden by a declared `Ontology`, whose relations are enforced (off-pattern edges are pruned). Through `GraphRAG`, the working ontology always has entity types (a new graph is seeded with the 11 defaults), so `entity_types` is overridden there; declare custom entity types on the `Ontology` instead.
- `CachedChunkExtraction(inner, graph_store, document_id)`: the decorator behind `update(cache_unchanged_chunks=True)`.

`DEFAULT_RELATION_TYPES` is exported at the top level.

**Entity extractors** (step 1 of `GraphExtraction`; subclass `EntityExtractor` and implement `extract_entities(text, entity_types, source_chunk_id)` for your own):
- `GLiNERExtractor(threshold=None, model_name=None, window_tokens=None, window_overlap=48, candidate_threshold=<25 % below threshold>)`: the default, local NER. `model_name=None` selects `urchade/gliner_medium-v2.1`; `threshold=None` selects the measured per-model value (0.75 for that model).
- `LLMExtractor(llm, threshold=0.75)`: LLM-based NER.
- `SpacyExtractor(model_name=None, labels=None, confidence=None)`: spaCy NER (`en_core_web_lg` by default), needs the `spacy` extra. Best as the second half of a `CompositeExtractor`.
- `CompositeExtractor(extractors, suppress_overlaps=True)`: runs several extractors in priority order.

**Coreference** (optional, `coref_resolver=`): `CorefResolver` (ABC), `FastCorefResolver(model_name="biu-nlp/lingmess-coref")` (needs the `fastcoref` extra).

### ResolutionStrategy (ABC)

```python
class ResolutionStrategy(ABC):
    @abstractmethod
    async def resolve(self, graph_data: GraphData, ctx: Context) -> ResolutionResult: ...
```

Runs per document, during ingest. Cross-document duplicates are merged by `finalize()`.

**Built-in:**
- `ExactMatchResolution(resolve_property="name", *, llm=None, force_summary_threshold=3, max_summary_tokens=500, cross_label_merge=False, cross_label_min_descriptions=3)`. `ingest()` uses `ExactMatchResolution(llm=None, cross_label_merge=False)`.
- `LLMVerifiedResolution(llm=None, embedder=None, *, hard_threshold=0.95, soft_threshold=0.65, max_llm_pairs=500, max_llm_concurrency=None, force_summary_threshold=3, max_summary_tokens=500, ann_top_k=50, batch_verification=True, verification_token_budget=4000, verification_max_pairs_per_call=5, cross_label_merge=True, cross_label_vector_door=0.60, cross_label_rank_floor=0.55, cross_label_max_pairs=200, cross_label_min_descriptions=3, unified_stage=True, unified_threshold=0.65, label_family_gate=True, cross_label_vote=True)`. Opt-in at `ingest()`. A pair whose names are equal once digits are removed (`GPT-3` / `GPT-4`, `Q1 2024` / `Q2 2024`) is never merged.

## Structured Ingestion

```python
from graphrag_sdk import (
    Ontology, TableMapping, Column, Link, MappingError,
    CsvRecordLoader, RecordLoaderStrategy, RecordBatch, TextLoader,
)
```

A table is declared on the ontology, next to the entity types, and then ingested through the ordinary `ingest()`. No model is involved in writing it: identity comes from a declared key, every property type is declared, and the same file always produces the same graph. A row and a prose mention of the same thing share one node from the first write. The full guide is [Structured Ingestion](/structured-ingestion); the runnable version is `examples/11_structured_ingestion.py`.

```python
ontology = Ontology(
    entities=[Entity(label="Person"), Entity(label="Organization")],
    tables=[
        TableMapping(
            source="employees.csv",
            label="Person",
            key="employee_id",
            name="full_name",
            properties={"age": Column("age", "INTEGER"), "title": "title"},
            links=[Link("WORKS_AT", to="Organization", by="org_id")],
        ),
    ],
)
rag = GraphRAG(connection=conn, llm=llm, embedder=embedder, ontology=ontology, enable_cypher=True)

result = await rag.ingest("data/employees.csv")     # StructuredIngestionResult
await rag.ingest("data/quarterly_report.pdf")       # prose, as before
report = await rag.finalize()                        # joins the two halves
```

### TableMapping

```python
@dataclass
class TableMapping:
    source: str                                  # file name; also the property signature
    label: str                                   # the label each row becomes
    key: str | None = None                       # column identifying the row; defaults to name
    name: str | None = None                      # column holding the display name
    properties: dict[str, Column | str] = field(default_factory=dict)  # property_name -> Column; a str means STRING
    links: list[Link] = field(default_factory=list)                    # columns that point at other entities
    standalone: bool = False                     # a new label that deliberately relates to nothing
    derived: bool = False                        # True for a mapping the SDK proposed
    description: str | None = None

    key_column: str                              # property: key, or name when no key was declared
    signature: str                               # property: the prefix every property is stored under
    def signed_name(self, prop: str) -> str      # e.g. "employees__age"
```

| Field | Description |
|-------|-------------|
| `source` | Matched to the ingested file on its basename. Also the **signature**: every property this table writes is stored as `<signature>__<property>` (`employees__age`), so two tables describing one entity cannot overwrite each other, and an extracted property (always unsigned) cannot collide with a declared one. Two sources that reduce to one signature (`hr.csv`, `HR.CSV`) are refused |
| `label` | May be new. A new label must connect to something (a `Link`, an entity in `entities`, or `standalone=True`), or `Ontology` raises `ValueError`. A label containing `\|` is refused |
| `key` | Stored on the node as `entity_key`; what links and re-syncs resolve through. Rows with a blank key are skipped and reported; a repeated key is logged. Defaults to `name`. Declare a separate key when names can repeat, change, or are what other tables link by. A property may not be named into the key's slot |
| `name` | Derives the node id, so a row and a prose mention of that name are one node. Two rows sharing a name fall back to their key and are reported, so an ambiguous mention joins neither |
| `properties` | Validated against the file's real header before anything is written. The signed columns reach the ontology as `Attribute(structured=True)` and are left out of the extraction prompt. Names must be identifiers without `__`; a header that is not an identifier is stored under a `col_` name |
| `links` | See `Link`. A label that a `Link` points at may have only one key column across tables |

`MappingError` (a `ValueError`) is raised for a declaration that does not fit (an unknown column, a cell that does not parse as its type, a row with more fields than the header, a label the sanitiser would rewrite), and the graph is left untouched.

### Column

```python
@dataclass(frozen=True)
class Column:
    name: str                     # the column in the source record
    type: str = "STRING"          # STRING, INTEGER, FLOAT, BOOLEAN, DATE, LIST
    description: str | None = None
```

Types are declared, never sniffed. Numbers may use either grouping convention (`1,234.56` and `1.234,56` both read as `1234.56`); a lone `1,234` is read as `1234` by `INTEGER` and refused as ambiguous by `FLOAT`; `INTEGER` refuses a fractional number; `FLOAT` refuses `nan` and `inf`; `BOOLEAN` reads `true/false`, `yes/no`, `1/0` and similar; `DATE` is stored as an ISO date string; `LIST` is parsed as a CSV row. A blank cell writes no property; a cell holding `0` is a value, not a blank.

### Link

```python
@dataclass
class Link:
    type: str                                    # relationship type, e.g. "WORKS_AT"
    to: str                                      # label of the target
    by: str                                      # column holding the target's key
    name: str | None = None                      # column holding the target's display name, if denormalised
    properties: dict[str, Column | str] = {}     # columns written onto the edge
    description: str | None = None
```

Written as a `RELATES` edge with `rel_type=type`, like every data edge. The target is **keyed, never named**: a missing target is created as a placeholder (`is_stub: true`) that is renamed in place, edges intact, when the owning table arrives; an existing target (another table's row, or an entity a document mentioned) only gains the key. A foreign key that more than one existing node answers to stays on a placeholder and is reported in `references_ambiguous`. Two links of one table may not point at the same `(to, by)`.

### Record loaders

```python
class RecordLoaderStrategy(ABC):
    @abstractmethod
    async def load_records(self, source: str, ctx: Context) -> RecordBatch: ...

@dataclass
class RecordBatch:
    open_records: Callable[[], Iterator[dict[str, Any]]]   # re-openable; the file is streamed twice
    columns: list[str]
    document_info: DocumentInfo
    record_count: int | None = None
    metadata: dict[str, Any] = field(default_factory=dict)

class CsvRecordLoader(RecordLoaderStrategy):
    def __init__(self, *, delimiter: str | None = None, encoding: str = "utf-8-sig", document_id: str | None = None): ...
```

`CsvRecordLoader` is the default; `delimiter=None` sniffs comma, semicolon, tab or pipe, and the default encoding reads UTF-8 with or without the byte-order mark Excel writes. The file is read once before anything is written: a row with more fields than the header is refused with its row number rather than loaded shifted. Implement `RecordLoaderStrategy` for another format and pass it as `ingest(..., record_loader=...)`.

### StructuredIngestionResult

Returned by `ingest()` for a table. It is a plain class in `graphrag_sdk.ingestion.structured_pipeline` (not a Pydantic model and not exported at the top level), with an `as_dict()` method that returns the fields worth reporting. It is not an `IngestionResult`: read `records`, not `chunks_indexed`.

| Field | Description |
|-------|-------------|
| `document_id` | The table's handle: its name, or the `document_id` you passed |
| `records`, `chunks` | Rows written. Each row is a `Chunk` (`kind: "record"`) carrying its cells beside the rendered text, under a `Document` named for the table. Records are not chained with `NEXT_CHUNK` |
| `entities`, `references`, `edges` | Nodes written, placeholders created for foreign keys, `RELATES` edges written |
| `rows_skipped`, `rows_in_source` | Rows dropped for a blank key, out of the rows read |
| `replaced_existing`, `no_op` | The source was already in the graph. `no_op` when the content hash (rows and mapping) was unchanged |
| `chunks_deleted`, `entities_deleted` | On a re-sync: rows gone from the export, and entities nothing mentions any more |
| `entities_moved`, `identity_moved` | Nodes moved to the id their name now gives them (a renamed row, or a placeholder a row filled in) and the `old_id -> new_id` map |
| `references_ambiguous` | `(label, key)` pairs a foreign key named that more than one existing node answers to; the edge was left on a placeholder |
| `incomplete_writes` | Writes the store reported short. When non-empty the content hash is withheld, so the next ingest of the file runs in full and repairs it |
| `content_hash` | The hash recorded for the source |

### How a table is written

- **Re-ingesting is a re-sync.** A table is a snapshot: a deleted row is removed, a blanked cell loses its column, a moved foreign key leaves its old target, and a node another source still mentions survives with the table's signed columns and identity retracted. A row the export dropped but another row still points at becomes a placeholder. The content hash covers the mapping, so re-declaring a type rewrites the source.
- **A Document records how it was written**, so `update()` cannot re-read a table as prose or a document as records. `update()`, `delete_document()` and `drop_table()` all take the table's name.
- **No mapping declared?** With a model, one is proposed (one call per table, up to 3 when a proposal does not fit the data and is sent back; never per row) from the measured columns, the first rows and the current ontology, held to the data (unique key, existing columns, known link targets, types the file can hold), stored with `derived=True` and reported by `finalize().proposed_mappings`. Without a model, or when no proposal fits, the file is read as-is: types measured over the whole file, the label from the filename, the leftmost unique-and-complete column as key, no name column. A file with no such column is refused. Declare a `TableMapping` to replace a proposal, or `drop_table()` to refuse it.
- **Ontology registration is additive.** Declared types reach the ontology so text-to-Cypher sees `age` as an `INTEGER`; an existing label is extended, not redeclared, and a type contradiction raises.

## Deduplication Judges

```python
from graphrag_sdk import (
    DedupJudge, LLMJudge,
    JudgeSet, JudgeEntity, JudgeType, JudgeAttribute,
    SetVerdict, JudgeGroup,
)
```

The judge decides which candidates in `finalize()`'s cross-document dedup are one real-world entity. The run nominates the candidates, checks every answer, and performs every merge; a judge never writes. Guide and examples: [Strategies](/strategies#7-dedupjudge).

### DedupJudge (ABC)

```python
class DedupJudge(ABC):
    @abstractmethod
    async def judge(self, sets: list[JudgeSet], *, retry: bool = False) -> list[SetVerdict | None]: ...

    def usage(self) -> dict[str, int]:   # optional running totals, e.g. {"llm_calls": 12}
        return {}
```

Return one verdict per set, in order, or `None` for a set it could not decide. A call that raises, or returns a list of another length, answers none of its sets. `retry=True` marks sets asked again because no usable answer came back.

### LLMJudge

```python
LLMJudge(
    llm: LLMInterface,
    *,
    max_concurrency: int | None = None,      # judge prompts in flight; None uses llm.max_concurrency
    min_output_tokens: int | None = 4_096,   # an output limit set lower on llm is raised to this for judge calls
)
```

Sets are packed into prompts of about 3,000 tokens; a retry asks one set per prompt. `min_output_tokens=None` keeps the LLM's own limit, for a server whose context window cannot hold a prompt plus 4,096 output tokens. `usage()` reports `llm_calls` and `llm_failed`. Use a gpt-4.1-class model.

### Judge input and output

```python
class JudgeAttribute(DataModel):
    name: str                  # e.g. "born", or "role (hr)" for one table's column
    type: str = "STRING"
    description: str = ""

class JudgeType(DataModel):
    label: str
    description: str = ""
    attributes: list[JudgeAttribute] = []

class JudgeEntity(DataModel):
    name: str
    labels: list[str] = []
    aliases: list[str] = []            # names it was already merged under
    description: str = ""
    attributes: dict[str, Any] = {}    # its values of the attributes its types declare

class JudgeSet(DataModel):
    entities: list[JudgeEntity]
    types: list[JudgeType] = []

class JudgeGroup(DataModel):
    members: list[int]                 # positions in JudgeSet.entities, two or more
    name: str | None = None            # merged name, one of the members' names or aliases
    keep: dict[str, int] = {}          # attribute -> member whose value the merged entity keeps

class SetVerdict(DataModel):
    groups: list[JudgeGroup] = []      # a member no group lists stands alone
```

Every `JudgeEntity` field is document text: data to judge, never instructions.

## Retrieval Strategies

### RetrievalStrategy (ABC)

Uses the Template Method pattern: `search()` validates, logs, calls `_execute()` and formats. Errors other than `RetrieverError` and `LatencyBudgetExceededError` are wrapped in `RetrieverError`.

```python
class RetrievalStrategy(ABC):
    def __init__(self, graph_store=None, vector_store=None): ...   # stored as self._graph, self._vector

    async def search(self, query, ctx=None, **kwargs) -> RetrieverResult: ...

    def set_ontology(self, ontology) -> None: ...

    @abstractmethod
    async def _execute(self, query, ctx, **kwargs) -> RawSearchResult: ...

    def _format(self, raw: RawSearchResult) -> RetrieverResult: ...   # override for custom formatting
```

`set_ontology()` is called by the facade on its configured retrieval strategy (the default, or the one passed as `GraphRAG(retrieval_strategy=...)`) whenever the working ontology changes: an evolution call, `set_ontology()`, a table declaring typed columns. A no-op by default; `MultiPathRetrieval` overrides it so generated Cypher sees the current schema. A strategy passed per call (`retrieve(strategy=...)`) is not updated; give it `ontology=` yourself.

### LocalRetrieval

```python
from graphrag_sdk.retrieval.strategies.local import LocalRetrieval

LocalRetrieval(graph_store, vector_store, embedder, top_k=5, include_entities=True)
```

Chunk vector search plus 1-hop entities. Items carry `score` and `metadata["chunk_id"]`.

### MultiPathRetrieval

```python
MultiPathRetrieval(
    graph_store, vector_store, embedder, llm,
    *,
    chunk_top_k=15,
    max_entities=30,
    max_relationships=20,
    rel_top_k=15,

```

The default strategy. `enable_cypher=True` adds the text-to-Cypher path (an extra LLM call per question (up to 3 when a generated query fails validation and is regenerated)); `ontology` is what that path generates against. ### VectorStore

```python

```

| Method | Signature | Description |
|--------|-----------|-------------|
| `create_chunk_vector_index` / `create_entity_vector_index` / `create_relates_vector_index` | `() -> bool` | Vector indexes on `Chunk`, `__Entity__`, `RELATES` |
| `create_chunk_fulltext_index` / `create_entity_fulltext_index` | `() -> bool` | Fulltext indexes on `Chunk(text)` and `__Entity__(name, description)` |

| `create_id_range_indices` | `() -> bool` | Range indexes on `id` for `Document`, `Chunk` and `__Entity__`. `GraphStore` indexes `id` and `entity_key` on each entity label the first time it writes to that label |
| `ensure_indices` | `() -> dict[str, bool]` | All of the above, idempotent; waits until FalkorDB reports every index built (up to 10 minutes). Returns `{}` when an earlier call already ensured them |

| `backfill_entity_embeddings` | `(batch_size=500) -> int` | Embed entities missing vectors. Not a dedup step: an entity it embeds counts as checked unless a `pending` record lists it; run `finalize(dedup_all=True)` once after it |

| `search_entities` | `(query_vector, top_k=5) -> list[dict]` | Entity vector search |
